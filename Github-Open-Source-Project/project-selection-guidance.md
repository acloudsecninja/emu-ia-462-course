# Project Selection Guidance

## How to Choose a Good Open-Source Project
Choose a project that is:
- public and open source
- well documented
- realistic to build locally
- relevant to security, Linux, networking, monitoring, DevOps, or virtualization
- not excessively large or opaque

## Good Project Characteristics
- has a README
- includes setup instructions
- clear dependency list
- active repository or recent commit history
- project purpose is understandable
- can be run in a container or local environment

## Avoid Projects That Are:
- too large to realistically manage in a short assignment
- missing installation instructions
- dependent on proprietary software
- broken or abandoned without usable documentation
- overly complex without a clear explanation

## Suggested Project Categories
- monitoring tools
- security tools
- Linux utilities
- web applications
- infrastructure tools
- reverse proxy or networking tools
- container-related tools

## Recommendation
Pick a project that you can explain clearly and that includes enough technical depth to show actual work without becoming overwhelming.
