# Operating System & Container Security Comparison

| Control Area | Linux | Windows | Docker |
| :--- | :--- | :--- | :--- |
| **Kernel Model** | Linux uses a monolithic kernel to manage hardware directly with full user-space isolation. *Key difference: It handles all core services natively within a single kernel space.* | Windows utilizes a hybrid NT kernel separating privileged Executive mode from user-mode subsystems. *Key difference: It relies on a microkernel-like architecture to load external subsystems.* | Shares the Linux kernel on Linux hosts or Windows kernel on Windows hosts to isolate processes. *Key difference: It does not have its own independent kernel.* |
| **Access Control** | Uses POSIX permissions and Mandatory Access Control (MAC) frameworks like SELinux. *Key difference: Permissions are deeply integrated with native file system attributes.* | Uses Discretionary Access Control Lists (DACLs) tied to centralized Security Identifiers (SIDs). *Key difference: Relies on robust, directory-based security tokens.* | Relies on dropping host capabilities and applying seccomp profiles to restrict system calls. *Key difference: It inherits host permissions rather than managing an isolated user database.* |
| **Auditing / Logging** | Relies on auditd and syslog for tracking kernel-level events and application logs. *Key difference: Uses highly modular, plain-text based logging facilities.* | Centralizes logs via the Windows Event Log accessed through the Event Viewer. *Key difference: Uses structured, binary-format event logs.* | Captures standard output (stdout/stderr) from containerized apps using logging drivers. *Key difference: Logs are ephemeral and disappear with the container unless explicitly routed to the host.* |
| **Hardening Standard** | Hardened using CIS Benchmarks to minimize daemon profiles and enforce MAC policies. *Key difference: Hardening is highly dependent on distribution-specific tools.* | Applies Microsoft Security Baselines and features like Credential Guard. *Key difference: Heavily enforced centrally through Group Policy Objects (GPOs).* | Hardened via CIS Docker Benchmarks enforcing rootless execution and read-only filesystems. *Key difference: Focuses strictly on limiting kernel syscalls rather than OS service configurations.* |
| **Common Attack Surface** | Vulnerable to SUID binary exploits and misconfigured sudoers files for local privilege escalation. *Key difference: Heavily targeted via exposed SSH or native bash vulnerabilities.* | Vulnerable to pass-the-hash attacks and Active Directory misconfigurations. *Key difference: RPC/SMB lateral movement is a primary attack vector.* | Vulnerable to exposed `docker.sock` endpoints and container escape vulnerabilities. *Key difference: Exploits often compromise the entire underlying host OS rather than just the application.*

### Hardening Priorities

For a brand-new Linux host, the priority hardening step is enforcing Mandatory Access Control (like SELinux) to strictly limit application permissions, as informed by the [Week 3 Slide Topic: Key OS Security Concepts] slide on Access Control Models. For Windows, reducing the attack surface by disabling unnecessary services is critical to prevent lateral movement, referencing the [Week 3 Slide Topic: Key OS Security Concepts] slide on Attack Surface Reduction. Finally, for Docker, configuring containers to run in rootless mode is essential to prevent a container escape, directly aligning with the Least Privilege principle covered in the [Week 3 Slide Topic: Key OS Security Concepts] presentation.
